## Current prototype compatibility

These files support the intended product story; generation does not implement missing features.

- Existing parsers can read WhatsApp exports, CSV rows, EML, PDF text, GPS and browser titles/URLs.
- CSV amounts remain content until typed financial normalization is implemented.
- The browser parser does not yet use visit_time_utc. Do not invent a visit timestamp when the parser omits it.
- Non-dialable DEMO phone IDs intentionally will not match Indian numeric-phone regexes.
- Tower records are a documented illustrative schema, not a validated real telecom-vendor format.
- The collector account is a potential investigation lead, not a proven person. Its handle-to-account mapping is stated in acquisition context.
- Deduplication, clock reconciliation, receipt comparison, tower analysis, replay and live cross-view filtering still require implementation.
- WhatsApp sources require day-first dates and Asia/Kolkata source timezone. The tablet's extra clock error is separate from timezone conversion.

## Integrity

manifest.json hashes final raw files. Run python3 demo-guide/verify_manifest.py from any directory. This checks the generated byte baseline; it is not a signature verifier and does not establish truth or pre-import custody. No deliberate file corruption or fake revision/EXIF detector result was added. The suspicious receipt is suspicious because of its content mismatch.

The generator recreates the repository root `evidence/` folder and the inventory under `docs/demo/riya/`. Regeneration replaces generated fixtures only; it does not import into a database.

## Evidence location and investigator workflow

All 15 original synthetic evidence files are together in the repository root `evidence/` folder. Run `python3 docs/demo/riya/verify_manifest.py` from the repository root to verify their original SHA-256 hashes. In the workspace, begin at **Upload evidence**, choose these files, review the list, then continue. Demo mode stages local files and uses preloaded sample analysis; signed-in mode creates a case and uploads to the backend before opening its analysis.
